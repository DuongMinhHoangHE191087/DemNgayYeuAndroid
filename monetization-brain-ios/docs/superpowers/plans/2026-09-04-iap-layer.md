# Phase 4 "IAP Layer" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Android's base IAP layer (`IapModels`/`FxRates`/`Entitlements`/`IapHelper`) to a
`StoreBackend`-protocol-abstracted Swift design, with the one real StoreKit 2 conformance living
in a new, separate `MonetizationBrainStoreKit` target.

**Architecture:** Five new files in `MonetizationBrainCore` (`IapModels.swift`, `StoreBackend.swift`,
`FxRates.swift`, `Entitlements.swift`, `IapHelper.swift`) plus one new SPM target
(`MonetizationBrainStoreKit`) with the real `StoreKit2Backend` conformance. See
`docs/superpowers/specs/2026-09-04-iap-layer-design.md` for the full design and every deviation's
rationale — this plan implements that spec section by section.

**Tech Stack:** Swift Package Manager, `MonetizationBrainCore`/`MonetizationBrainStoreKit`
targets, XCTest, iOS 15+/macOS 12+, StoreKit 2 (first-party, no new SPM dependency).

**Security note:** this is payment/financial code. A `security-reviewer` pass is required before
this branch merges, in addition to the usual whole-branch review — see spec §7.

## Global constraints (apply to every task below)

- **NSLock discipline:** lock only around actual mutable state. Never call `lock.lock()`/
  `unlock()` directly inside an `async` function body — route through a synchronous private
  helper. NSLock is non-reentrant.
- **No force-unwraps (`!`)** in new production code.
- **`price_micros` conversion uses exact `Decimal` arithmetic, never `Double`** — converting
  StoreKit 2's `Decimal` price through `Double` first would reintroduce the floating-point
  imprecision `Decimal` exists to avoid (spec §3.5). Use `Decimal`'s own multiply/round or
  `NSDecimalNumber`'s exact operations.
- **The `iap_purchase` event's field NAMES are a locked, byte-for-byte wire contract** — `product_id`,
  `order_id`, `price_micros`, `currency_code`, `quantity`, `channel`, `is_subscription` (`.int`
  0/1, not `.bool` — matches Phase 3's `is_holdout` precedent), `purchase_token`. No `screen_name`
  field this phase (spec §5 — no equivalent concept exists yet on iOS; do not invent one).
- **`AdsBrain.shared.onPurchase(usd:)` must be called unconditionally on every successful
  purchase, using `FxRates.toUsd(...) ?? 0.0`** — never skip the call when the currency is
  unknown (spec §3.8). This is the payer-guardrail invariant: `purchaseCountLifetime` (which
  `onPurchase` increments regardless of `usd`) is what `GuardrailEngine`'s payer-protection rule
  reads, not a USD total.
- **`Entitlements.sync` REPLACES the owned set, never unions it.** This is the one-line mechanism
  that lets a lapsed subscription lose entitlement — get it wrong and every subscriber gets free
  entitlement forever once they've ever owned the product once.
- **Three independent, isolated reporting paths on every successful purchase** (spec §4's
  `IapHelper` section): the `iap_purchase` event, `AdsBrain.shared.onPurchase`, and a documented-
  but-not-implemented AppsFlyer slot (deferred, spec §1). One failing must never block another —
  Android's own `reportPurchase()` wraps each in its own try/catch for exactly this reason; Swift
  has no exceptions for this class of error, so each step is a plain sequential call with no
  shared early-exit between them (a thrown error from event emission, if any ever becomes
  possible, must not prevent the `AdsBrain` call from running).
- **`purchaseListener` is single-slot, last-set-wins** — not a list, not a stream. Fires for every
  processed transaction from every trigger path (`purchase(_:)`, `restorePurchases()`, the
  background `transactionUpdates()` stream), after `reportPurchase` completes.
- Every task: run `swift build && swift test` before committing; report the full suite's pass
  count in the task report, not just the new file's tests.
- Per-file test fakes: this codebase's established convention is a PRIVATE, per-test-file
  redeclaration of small fakes (`InMemoryStore: BrainKeyValueStore`, `FakeEventSink: EventSink`)
  rather than one shared fake file — follow that convention, do not introduce a shared fakes file.

```swift
/// Public IAP data types — deliberately never leak a StoreKit type into this SDK's own public
/// API (mirrors Android's `IapModels.kt`: this is a published artifact, and Google has broken
/// Play Billing's public shape once already; wrapping in an owned model lets the vendor
/// implementation change without breaking every integrator).

/// StoreKit 2's real 4-case product type — NOT Android's coarser `{INAPP, SUBS}` + a separately
/// app-declared consumable set. `Product.ProductType` already tells us consumability directly;
/// Android needed the app to declare it because Play's `ProductDetails` doesn't (see design spec
/// §3.3 for the full rationale).
public enum IapProductType: Sendable, Equatable, CaseIterable {
    case consumable
    case nonConsumable
    case autoRenewable
    case nonRenewing

    public var isSubscription: Bool {
        self == .autoRenewable || self == .nonRenewing
    }
}

/// Payment channel (Android doc 26 §C.2: revenue must be reported PER channel — margins differ
/// significantly by channel). `.webShop` has no execution path yet this phase — kept only so the
/// event schema doesn't need to change when that channel arrives, matching Android's own
/// forward-compat placeholder.
public enum PurchaseChannel: String, Sendable, Equatable, CaseIterable {
    case appStore = "APP_STORE"
    case webShop = "WEB_SHOP"
}

/// Transaction state. `.pending` is a real, distinct StoreKit 2 concept (Ask-to-Buy/SCA flows via
/// `Product.PurchaseResult.pending`) — not invented to mirror Android's PENDING 1:1. See design
/// spec §3.6 for why this phase does NOT replicate Android's INAPP/SUBS grace-period asymmetry.
public enum IapPurchaseState: String, Sendable, Equatable, CaseIterable {
    case purchased = "PURCHASED"
    case pending = "PENDING"
    case unspecified = "UNSPECIFIED"
}

/// A product with price information already fetched from the store.
///
/// `priceMicros`/`currencyCode` keep the store's ORIGINAL unit, never pre-converted — client-side
/// conversion is where rounding error and stale rates creep in; the backend has the real rate
/// table, so conversion belongs there (see `FxRates`).
public struct IapProduct: Sendable, Equatable {
    public let productId: String
    public let type: IapProductType
    public let formattedPrice: String
    public let priceMicros: Int64
    public let currencyCode: String
    public let title: String
    public let description: String

    public init(
        productId: String,
        type: IapProductType,
        formattedPrice: String,
        priceMicros: Int64,
        currencyCode: String,
        title: String = "",
        description: String = ""
    ) {
        self.productId = productId
        self.type = type
        self.formattedPrice = formattedPrice
        self.priceMicros = priceMicros
        self.currencyCode = currencyCode
        self.title = title
        self.description = description
    }
}

/// A transaction that occurred.
///
/// `priceMicros`/`currencyCode` are joined in from the matching cached `IapProduct` at handling
/// time — a raw transaction from the store doesn't carry price by itself; without this join the
/// revenue event has no amount.
public struct IapPurchase: Sendable, Equatable {
    public let productId: String
    public let orderId: String
    public let purchaseToken: String
    public let purchaseTimeMs: Int64
    public let state: IapPurchaseState
    public let isFinished: Bool
    public let isAutoRenewing: Bool
    public let quantity: Int
    public let priceMicros: Int64
    public let currencyCode: String
    public let channel: PurchaseChannel

    public init(
        productId: String,
        orderId: String,
        purchaseToken: String,
        purchaseTimeMs: Int64,
        state: IapPurchaseState,
        isFinished: Bool,
        isAutoRenewing: Bool,
        quantity: Int,
        priceMicros: Int64,
        currencyCode: String,
        channel: PurchaseChannel = .appStore
    ) {
        self.productId = productId
        self.orderId = orderId
        self.purchaseToken = purchaseToken
        self.purchaseTimeMs = purchaseTimeMs
        self.state = state
        self.isFinished = isFinished
        self.isAutoRenewing = isAutoRenewing
        self.quantity = quantity
        self.priceMicros = priceMicros
        self.currencyCode = currencyCode
        self.channel = channel
    }
}

/// Result of one purchase attempt — enough for the caller to show the right message without
/// knowing any store-specific error code.
public enum IapResult: Sendable, Equatable {
    case success(IapPurchase)
    case pending(IapPurchase)
    case userCanceled
    case alreadyOwned
    case failed(code: Int, message: String)
}
```

```swift
/// The seam between `IapHelper`'s orchestration logic and a real store. `IapHelper` never
/// imports StoreKit directly — every store interaction goes through this protocol, so the
/// orchestration logic is unit-testable with an in-memory fake, the same architectural move this
/// codebase already made for `RemoteConfigProvider` (Phase 1) and `BrainKeyValueStore` (Phase 3).
/// The one real conformance (`StoreKit2Backend`) lives in a separate `MonetizationBrainStoreKit`
/// target — see design spec §2.
public protocol StoreBackend: Sendable {
    /// Fetches price/metadata for the given product identifiers. Products the store doesn't
    /// recognize are simply absent from the result — never a partial failure for the whole call.
    func products(for identifiers: [String]) async throws -> [IapProduct]

    /// Initiates a purchase. Throws only for a genuine call-level failure (e.g. the store
    /// couldn't even be reached) — a user-facing outcome like cancellation is a normal
    /// `IapResult` case, not a thrown error.
    func purchase(_ product: IapProduct) async throws -> IapResult

    /// Snapshot of everything currently entitled, as of right now — used by `restorePurchases()`.
    /// A stream (not a single call returning `[IapPurchase]`) so the real conformance can finish
    /// each transaction as it iterates, matching how `Transaction.currentEntitlements` is itself
    /// an `AsyncSequence` in StoreKit 2.
    func currentEntitlements() -> AsyncStream<IapPurchase>

    /// The ongoing stream of transactions arriving outside any in-process `purchase(_:)` call —
    /// restored on another device, completed after being killed mid-purchase, etc. Persistent
    /// for the lifetime of the process; `IapHelper` consumes it via a background task started in
    /// `configure(_:)`.
    func transactionUpdates() -> AsyncStream<IapPurchase>

    /// Finalizes a transaction — StoreKit 2's single `Transaction.finish()` call, unlike Play
    /// Billing's two-call acknowledge/consume split (see design spec §3.2). Called exactly once
    /// per successfully processed purchase, from every trigger path.
    func finish(_ purchase: IapPurchase) async
}
```

```swift
import Foundation

/// Converts a store price to USD — **only when the rate is actually known**, never a guess.
///
/// ═══ WHY NIL, NOT A GUESS ═══
///
/// The store reports price in local currency. Stuffing that number directly into
/// `PlayerState.purchaseValueLifetimeUsd` would record a 99,000 VND transaction as "99000 USD" —
/// a type error that never crashes, so nobody notices (matches Android's `FxRates.kt` doc
/// comment verbatim).
///
/// Embedding a rate table in code isn't the fix either — rates change daily, this SDK ships
/// monthly at best. So only `USD` is a compile-time constant; every other rate must be loaded
/// remotely (a policy artifact, key `fx_rates` on Android — the same shape applies here) and can
/// update without a release.
///
/// ═══ THE TRUTH STAYS INTACT AT THE EVENT LEVEL ═══
///
/// Failing to convert does NOT lose data: the `iap_purchase` event always sends the original
/// `price_micros`/`currency_code` to the backend, which has the real rate. The only thing this
/// affects is the on-device accumulated USD total, and it's left honestly blank rather than
/// filled with a fabricated number.
public enum FxRates {
    private static let microsPerUnit = 1_000_000.0
    private static let lock = NSLock()
    private static var rates: [String: Double] = [:]

    /// Loads "1 unit of currency = ? USD". REPLACES the whole table.
    ///
    /// Replace, not merge: merging would keep a stale rate for a currency code the newest
    /// artifact dropped — exactly the kind of stale number this mechanism exists to avoid.
    public static func setRates(_ newRates: [String: Double]) {
        lock.lock()
        rates = newRates
            .filter { $0.value > 0.0 && $0.value.isFinite }
            .reduce(into: [String: Double]()) { result, entry in
                result[entry.key.uppercased()] = entry.value
            }
        lock.unlock()
    }

    public static func reset() {
        lock.lock()
        rates = [:]
        lock.unlock()
    }

    /// Number of non-USD currencies currently known — for surfacing in an artifact-load report.
    public static func knownCurrencyCount() -> Int {
        lock.lock()
        defer { lock.unlock() }
        return rates.count
    }

    /// - Returns: the USD value, or `nil` if `currencyCode`'s rate isn't known. Callers MUST
    ///   treat `nil` by omitting the value, never by substituting `0.0` — "value unknown" and
    ///   "worth zero" are different facts.
    public static func toUsd(priceMicros: Int64, currencyCode: String) -> Double? {
        guard !currencyCode.isEmpty else { return nil }
        let code = currencyCode.uppercased()
        let amount = Double(priceMicros) / microsPerUnit
        if code == "USD" { return amount }
        lock.lock()
        let rate = rates[code]
        lock.unlock()
        guard let rate else { return nil }
        return amount * rate
    }
}
```

```swift
/// The player's currently-owned products, and the sole bridge point to an ad-control facade.
///
/// ═══ WHY THIS TYPE EXISTS ═══
///
/// Android doc 27 §B.3 records a real anti-pattern from a competitor teardown: **a subscriber
/// still sees ads**. The root cause wasn't malice — purchase state and the ad-disable flag were
/// two separate things, owned by two separate pieces of code, and they drifted. This type is the
/// ONE place: every entitlement change flows through `recompute()`, and `recompute()` is the
/// ONLY caller of the (not-yet-existing on iOS, see design spec §1) ad-control facade — no other
/// code path may call it directly.
///
/// ═══ LIMITS THAT MUST BE STATED PLAINLY ═══
///
/// This is CLIENT-SIDE state, trusting whatever the store reports on-device. It is NOT a
/// fraud-resistant source of truth — server-side entitlement verification (design spec §1,
/// deferred) is the real source of truth once it exists. For `hasRemoveAds()`, the risk is
/// acceptable: the worst case of being fooled is someone seeing fewer ads. **This type must
/// never be used to grant an item with real redeemable value** until server-side receipt
/// verification exists.
public final class Entitlements: @unchecked Sendable {
    public static let shared = Entitlements()

    private static let activeKey = "iap_active_products"
    private static let removeAdsKey = "iap_remove_ads_products"
    private static let separator = "|"

    private let lock = NSLock()
    private let store: BrainKeyValueStore
    private var active: Set<String>
    private var _removeAdsProductIds: Set<String>

    public init(store: BrainKeyValueStore = UserDefaultsBrainStore()) {
        self.store = store
        self.active = Self.loadSet(store: store, key: Self.activeKey)
        self._removeAdsProductIds = Self.loadSet(store: store, key: Self.removeAdsKey)
    }

    private static func loadSet(store: BrainKeyValueStore, key: String) -> Set<String> {
        guard let raw = store.string(forKey: key), !raw.isEmpty else { return [] }
        return Set(raw.split(separator: Character(separator)).map(String.init))
    }

    // MARK: - Read

    public func hasRemoveAds() -> Bool {
        lock.lock()
        defer { lock.unlock() }
        return !active.isDisjoint(with: _removeAdsProductIds)
    }

    public func isActive(_ productId: String) -> Bool {
        lock.lock()
        defer { lock.unlock() }
        return active.contains(productId)
    }

    public func activeProductIds() -> Set<String> {
        lock.lock()
        defer { lock.unlock() }
        return active
    }

    // MARK: - Configuration

    /// Which products disable ads. Usually sourced from remote config so it can change without a
    /// release. Recomputes `hasRemoveAds()` immediately: someone who already owns a product that
    /// TODAY gets classified as remove-ads must benefit right away, not on their next purchase.
    public var removeAdsProductIds: Set<String> {
        get {
            lock.lock()
            defer { lock.unlock() }
            return _removeAdsProductIds
        }
        set {
            lock.lock()
            _removeAdsProductIds = newValue
            store.setString(newValue.joined(separator: Self.separator), forKey: Self.removeAdsKey)
            lock.unlock()
        }
    }

    // MARK: - Write

    public func grant(_ productId: String) {
        lock.lock()
        let inserted = active.insert(productId).inserted
        if inserted {
            store.setString(active.joined(separator: Self.separator), forKey: Self.activeKey)
        }
        lock.unlock()
    }

    public func revoke(_ productId: String) {
        lock.lock()
        let removed = active.remove(productId) != nil
        if removed {
            store.setString(active.joined(separator: Self.separator), forKey: Self.activeKey)
        }
        lock.unlock()
    }

    /// Resets entitlement to EXACTLY what the store reports right now.
    ///
    /// REPLACES, never unions — this is the crux. `queryOwned`/`currentEntitlements` returns
    /// what's owned AT THIS MOMENT; a cancelled subscription is simply absent from that set.
    /// Unioning would give a cancelled subscriber permanent free entitlement on that device.
    public func sync(_ productIds: Set<String>) {
        lock.lock()
        guard active != productIds else { lock.unlock(); return }
        active = productIds
        store.setString(active.joined(separator: Self.separator), forKey: Self.activeKey)
        lock.unlock()
    }

    /// Test-only: clears all entitlement state.
    func resetForTest() {
        lock.lock()
        active = []
        _removeAdsProductIds = []
        store.removeObject(forKey: Self.activeKey)
        store.removeObject(forKey: Self.removeAdsKey)
        lock.unlock()
    }
}
```

Note: `hasRemoveAds()` uses `!active.isDisjoint(with:)` rather than Android's `active.any { it in
removeAdsProducts }` — the same "is there any overlap" check, expressed via `Set`'s own built-in
operation instead of a manual loop (behaviorally identical, more idiomatic Swift). Preserve the
behavior, not the loop shape.

```swift
import Foundation

/// Orchestrates purchases against an injected `StoreBackend` — the real store adapter (StoreKit
/// 2) lives in a separate `MonetizationBrainStoreKit` target and is never imported here.
///
/// ═══ WHERE THIS SITS IN THE PRODUCT ═══
///
/// This is the piece that unlocks most of the IAP-related roadmap: before it, `ActionMode
/// .iapOffer` is an enum case with nothing behind it, because the SDK has no way to know who has
/// bought what. With it, three things become real:
/// 1. **A payer signal into the brain** — `AdsBrain.shared.onPurchase(usd:)` is called
///    automatically, belief shifts toward the payer segment, and ad-pressure guardrails ease off
///    for someone who just paid.
/// 2. **Revenue reporting** — the `iap_purchase` event carries `price_micros`/`currency_code`/
///    `channel`, letting ARPDAU be computed across both IAP and ad revenue.
/// 3. **Entitlement flows into the ad layer** — `Entitlements` turns ads off for a subscriber
///    (once an ad-control facade exists — see design spec §1).
///
/// ═══ WHAT THIS DELIBERATELY DOES NOT DO ═══
///
/// - **No server-side receipt verification.** No backend exists for it yet (design spec §1).
///   `Entitlements` here should only ever be used for `hasRemoveAds()`, never for redeemable-
///   value items, until that verification exists.
/// - **No paywall.** The host app owns purchase-initiation UI entirely.
public final class IapHelper: @unchecked Sendable {
    public static let shared = IapHelper()

    public struct Configuration: Sendable {
        public let backend: StoreBackend
        public let eventSink: EventSink
        public let playerId: String

        public init(backend: StoreBackend, eventSink: EventSink, playerId: String) {
            self.backend = backend
            self.eventSink = eventSink
            self.playerId = playerId
        }
    }

    private let lock = NSLock()
    private var configuration: Configuration?
    private var productCache: [String: IapProduct] = [:]
    private var declaredProductIds: [String] = []

    /// Every processed transaction, from every trigger path. Single-slot, last-set-wins — see
    /// design spec §4's `IapHelper` section for why this isn't a list or a stream.
    public var purchaseListener: (@Sendable (IapResult) -> Void)?

    public init() {}

    public func isReady() -> Bool {
        lock.lock()
        defer { lock.unlock() }
        return configuration != nil
    }

    /// Wires the facade up. Idempotent-in-spirit: safe to call again with a new configuration
    /// (e.g. a different player after a re-login) — this phase does not special-case that beyond
    /// simply replacing the stored configuration; product/entitlement state itself is not
    /// player-scoped the way `AdsBrain`'s `SessionState` is (Android's own `IapHelper`/
    /// `Entitlements` are device-scoped singletons too, not per-player).
    public func configure(_ configuration: Configuration) async {
        storeConfiguration(configuration)
    }

    private func storeConfiguration(_ configuration: Configuration) {
        lock.lock()
        self.configuration = configuration
        lock.unlock()
    }

    private func currentConfiguration() -> Configuration? {
        lock.lock()
        defer { lock.unlock() }
        return configuration
    }

    /// Declares which products this app sells. Call before `queryProducts()`/`purchase(_:)` —
    /// an undeclared product id will never be found in the catalog.
    public func setProducts(_ productIds: [String]) {
        lock.lock()
        declaredProductIds = productIds
        lock.unlock()
    }

    public func productFor(_ productId: String) -> IapProduct? {
        lock.lock()
        defer { lock.unlock() }
        return productCache[productId]
    }

    public func products() -> [IapProduct] {
        lock.lock()
        defer { lock.unlock() }
        return Array(productCache.values)
    }

    /// Fetches price/metadata for every declared product and caches it. Cached prices are what
    /// `purchase(_:)` and the `iap_purchase` event's price fields read — a purchase for a product
    /// never queried has no price to report.
    @discardableResult
    public func queryProducts() async -> [IapProduct] {
        guard let configuration = currentConfiguration() else { return [] }
        let ids = currentDeclaredProductIds()
        guard !ids.isEmpty else { return [] }
        do {
            let fetched = try await configuration.backend.products(for: ids)
            cacheProducts(fetched)
            return fetched
        } catch {
            return []
        }
    }

    private func currentDeclaredProductIds() -> [String] {
        lock.lock()
        defer { lock.unlock() }
        return declaredProductIds
    }

    private func cacheProducts(_ fetched: [IapProduct]) {
        lock.lock()
        for product in fetched { productCache[product.productId] = product }
        lock.unlock()
    }

    /// Initiates a purchase. Returns `.failed` immediately (no store call at all) if the product
    /// hasn't been queried/cached yet — the caller needs to know why nothing happened rather than
    /// silently seeing no response.
    @discardableResult
    public func purchase(_ productId: String) async -> IapResult {
        guard let configuration = currentConfiguration() else {
            return .failed(code: -1, message: "not configured")
        }
        guard let product = productFor(productId) else {
            return .failed(code: -1, message: "product not ready — call queryProducts() first")
        }
        let result: IapResult
        do {
            result = try await configuration.backend.purchase(product)
        } catch {
            result = .failed(code: -1, message: "\(error)")
        }
        let final = await handle(result, configuration: configuration)
        purchaseListener?(final)
        return final
    }

    /// Shared handling for a raw `IapResult` from ANY trigger path (a direct `purchase(_:)` call,
    /// a `currentEntitlements()` item during restore — Task 6, or a `transactionUpdates()` item —
    /// Task 6): grants entitlement + finalizes + reports, only for `.success`. Every other case
    /// passes through unchanged — a pending/cancelled/failed/already-owned result never touches
    /// entitlements or reporting.
    private func handle(_ result: IapResult, configuration: Configuration) async -> IapResult {
        guard case .success(let purchase) = result else { return result }
        Entitlements.shared.grant(purchase.productId)
        await configuration.backend.finish(purchase)
        await reportPurchase(purchase, configuration: configuration)
        return result
    }

    /// A successful transaction must reach every reporting destination independently — one
    /// failing (or, this phase, one not yet existing — see the AppsFlyer note below) must never
    /// block another. Two destinations exist this phase; a third (AppsFlyer/attribution revenue
    /// reporting) is intentionally absent — see design spec §1 — add it here, as an equally
    /// independent step, when an attribution SDK wrapper exists on this port.
    private func reportPurchase(_ purchase: IapPurchase, configuration: Configuration) async {
        await configuration.eventSink.send(SdkEvent(
            eventName: "iap_purchase",
            eventData: [
                "product_id": .string(purchase.productId),
                "order_id": .string(purchase.orderId),
                "price_micros": .int(Int(purchase.priceMicros)),
                "currency_code": .string(purchase.currencyCode),
                "quantity": .int(purchase.quantity),
                "channel": .string(purchase.channel.rawValue),
                "is_subscription": .int((productFor(purchase.productId)?.type.isSubscription ?? false) ? 1 : 0),
                "purchase_token": .string(purchase.purchaseToken)
            ],
            userProperty: UserProperty(userId: configuration.playerId)
        ))
        // Quantity of currency lost to unknown FX is left honestly blank, never guessed — see
        // FxRates. The purchase still counts toward purchaseCountLifetime regardless (the
        // payer-guardrail invariant reads that count, never a USD total — design spec §3.8).
        let usd = FxRates.toUsd(priceMicros: purchase.priceMicros, currencyCode: purchase.currencyCode)
        await AdsBrain.shared.onPurchase(usd: usd ?? 0.0)
    }
}
```

```swift
        private func recordFinishedPurchase(_ purchase: IapPurchase) {
            lock.lock()
            finishedPurchases.append(purchase)
            lock.unlock()
        }
```

```swift
    public func configure(_ configuration: Configuration) async {
        storeConfiguration(configuration)
        startConsumingTransactionUpdates(configuration: configuration)
    }

    private func startConsumingTransactionUpdates(configuration: Configuration) {
        lock.lock()
        updatesTask?.cancel()
        // `backend.transactionUpdates()` is called SYNCHRONOUSLY here, outside the `Task` below
        // — not inside it. `AsyncStream`'s build closure runs synchronously at construction, so
        // this is what actually registers the continuation; calling it from inside `Task { ... }`
        // instead would defer that registration until the Task gets its first executor turn,
        // which can race with (and silently lose) anything the backend emits between
        // `configure(_:)` returning and that first turn actually running. Vend the stream here,
        // hand the already-live stream to the Task purely for iteration.
        let backend = configuration.backend
        let stream = backend.transactionUpdates()
        updatesTask = Task { [weak self] in
            for await purchase in stream {
                guard let self else { return }
                guard let currentConfiguration = self.currentConfiguration() else { continue }
                let final = await self.handle(.success(purchase), configuration: currentConfiguration)
                self.purchaseListener?(final)
            }
        }
        lock.unlock()
    }
```

```swift
    }
```

```swift
import StoreKit
import MonetizationBrainCore

/// The one real `StoreBackend` conformance — StoreKit 2. `MonetizationBrainCore` never imports
/// `StoreKit` directly; this target exists solely to isolate that import, mirroring
/// `MonetizationBrainUMP`'s isolation of `GoogleUserMessagingPlatform` (design spec §2).
/// A `final class`, not a `struct`: `finish(_:)` needs to look up the ORIGINAL `Transaction`
/// object for a given `IapPurchase` (StoreKit 2's `finish()` is a method on `Transaction` itself,
/// and re-deriving a `Transaction` from scratch isn't possible — it's not something you
/// reconstruct from an id). A struct's value semantics would make a cache populated by one
/// method invisible to another; a class with `NSLock`-protected shared storage is the correct
/// shape here, mirroring every other stateful type in this codebase.
public final class StoreKit2Backend: StoreBackend, @unchecked Sendable {
    private let lock = NSLock()
    /// Caches the real `Transaction` behind every `IapPurchase` this instance has ever produced,
    /// keyed by `orderId` (`"\(transaction.id)"`) — populated everywhere an `IapPurchase` is
    /// built, consumed only by `finish(_:)`. Without this, `finish(_:)` would have no way to
    /// recover the transaction object StoreKit 2's `finish()` requires, for ANY purchase not
    /// still present in `Transaction.currentEntitlements` (every consumable, the instant it's
    /// been consumed once — which is exactly when `finish()` is called).
    private var transactionsByOrderId: [String: Transaction] = [:]

    public init() {}

    public func products(for identifiers: [String]) async throws -> [IapProduct] {
        let products = try await Product.products(for: identifiers)
        return products.map(Self.toIapProduct)
    }

    public func purchase(_ product: IapProduct) async throws -> IapResult {
        let storeProducts = try await Product.products(for: [product.productId])
        guard let storeProduct = storeProducts.first else {
            return .failed(code: -1, message: "product not found in store catalog")
        }
        let result = try await storeProduct.purchase()
        switch result {
        case .success(let verification):
            switch verification {
            case .verified(let transaction):
                return .success(cache(transaction, product: storeProduct))
            case .unverified:
                return .failed(code: -1, message: "transaction failed StoreKit verification")
            }
        case .userCancelled:
            return .userCanceled
        case .pending:
            // No verified Transaction exists yet for a pending result — build the IapPurchase
            // from the product/request we already have, matching Android's own contract that a
            // pending purchase must never be granted entitlement (design spec §3.6). Nothing to
            // cache: there is no Transaction object to look up later for this case.
            return .pending(IapPurchase(
                productId: product.productId, orderId: "", purchaseToken: "",
                purchaseTimeMs: Int64(Date().timeIntervalSince1970 * 1000), state: .pending,
                isFinished: false, isAutoRenewing: false, quantity: 1,
                priceMicros: product.priceMicros, currencyCode: product.currencyCode
            ))
        @unknown default:
            return .failed(code: -1, message: "unknown StoreKit purchase result")
        }
    }

    public func currentEntitlements() -> AsyncStream<IapPurchase> {
        AsyncStream { continuation in
            Task { [weak self] in
                for await verification in Transaction.currentEntitlements {
                    guard case .verified(let transaction) = verification, let self else { continue }
                    let products = try? await Product.products(for: [transaction.productID])
                    continuation.yield(self.cache(transaction, product: products?.first))
                }
                continuation.finish()
            }
        }
    }

    public func transactionUpdates() -> AsyncStream<IapPurchase> {
        AsyncStream { continuation in
            Task { [weak self] in
                for await verification in Transaction.updates {
                    guard case .verified(let transaction) = verification, let self else { continue }
                    let products = try? await Product.products(for: [transaction.productID])
                    continuation.yield(self.cache(transaction, product: products?.first))
                }
            }
        }
    }

    public func finish(_ purchase: IapPurchase) async {
        let transaction = takeCachedTransaction(orderId: purchase.orderId)
        await transaction?.finish()
    }

    /// Builds the `IapPurchase` AND records the real `Transaction` behind it, under one lock —
    /// every path that produces an `IapPurchase` (purchase/restore/background update) goes
    /// through this, so `finish(_:)` can always find what it needs later regardless of which
    /// path produced the purchase.
    private func cache(_ transaction: Transaction, product: Product?) -> IapPurchase {
        let purchase = Self.toIapPurchase(transaction, product: product)
        lock.lock()
        transactionsByOrderId[purchase.orderId] = transaction
        lock.unlock()
        return purchase
    }

    private func takeCachedTransaction(orderId: String) -> Transaction? {
        lock.lock()
        defer { lock.unlock() }
        return transactionsByOrderId.removeValue(forKey: orderId)
    }

    private static func toIapProduct(_ product: Product) -> IapProduct {
        IapProduct(
            productId: product.id,
            type: toProductType(product.type),
            formattedPrice: product.displayPrice,
            priceMicros: toPriceMicros(product.price),
            currencyCode: product.priceFormatStyle.currencyCode,
            title: product.displayName,
            description: product.description
        )
    }

    private static func toIapPurchase(_ transaction: Transaction, product: Product?) -> IapPurchase {
        IapPurchase(
            productId: transaction.productID,
            orderId: "\(transaction.id)",
            purchaseToken: transaction.jwsRepresentation,
            purchaseTimeMs: Int64(transaction.purchaseDate.timeIntervalSince1970 * 1000),
            state: .purchased,
            isFinished: false,
            isAutoRenewing: transaction.productType == .autoRenewable,
            quantity: transaction.purchasedQuantity,
            priceMicros: product.map { toPriceMicros($0.price) } ?? 0,
            currencyCode: product?.priceFormatStyle.currencyCode ?? ""
        )
    }

    private static func toProductType(_ type: Product.ProductType) -> IapProductType {
        switch type {
        case .consumable: return .consumable
        case .nonConsumable: return .nonConsumable
        case .autoRenewable: return .autoRenewable
        case .nonRenewing: return .nonRenewing
        default: return .nonConsumable
        }
    }

    /// Exact `Decimal` arithmetic — never through `Double` (design spec §3.5). Lossless for any
    /// real-world currency amount.
    private static func toPriceMicros(_ price: Decimal) -> Int64 {
        let micros = price * 1_000_000
        let rounded = NSDecimalNumber(decimal: micros).rounding(accordingToBehavior: nil)
        return rounded.int64Value
    }
}
```

Note `transactionsByOrderId` grows unboundedly for entitlements that are never finished (e.g. a
`currentEntitlements()`/`transactionUpdates()` item `IapHelper` chooses not to call `finish(_:)`
on for some reason) — acceptable for this phase (every path `IapHelper` actually has DOES call
`finish(_:)` on everything it processes), but worth a one-line note in the class doc if a future
phase adds a path that produces `IapPurchase`s without ever finishing them.
