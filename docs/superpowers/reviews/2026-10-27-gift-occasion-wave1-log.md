- Round 2 design for U05: the test helpers pre-save the language instead of calling the action under test, so the only `requestResync()` in a test is the one it asks for.
- Round 3 design for U13a (boot-time source validation): `rearmFromBootCopy` runs six steps in this order. (1) No copy: return 0. (2) The copy's token differs from the current vault token: return 0 and leave the copy. (3) Owner resolution: the guest token has no owner; otherwise the owner is the account whose scope token equals the copy's token, and it must exist and have a non-blank `sessionToken`. (4) Persisted termination of the owner's own relationships. (5) Source check of every copy, guest copy included, against Room. (6) Re-arm. Codex suggested a write fence (fence boot-copy writes by the source scope of the date and relationship inputs, with VM ownership in W4). It was not adopted: the stale re-arm after sign-out is existing in-memory behavior, the fence would touch six VM assignment sites (VM:650, :661, :681, :725, :1136, :1222) and move InLoveViewModel into W4, and boot-time validation stops the same replay without touching the ViewModel. The regression Codex asked for is adopted as test (w4). What stays is recorded in R1 limits (1)-(7) and in the two new "Skipped" bullets of section 10.
