**Goal:** Fix the Wave-1 correctness, honesty and reach problems in gift suggestions, holiday data, love milestones and reminders that the research doc found. Stay inside Room v14, add no new dependency, and change no product direction.

**Architecture:** Every change is local to an existing class. No new module, interface or layer. Rules that live in two places become one: milestones use `LoveMilestoneRules`, notification texts use `ReminderTexts`. The only new persistent state is one private SharedPreferences file for the boot re-arm (U-13a). `LoveAnniversaryMilestoneScheduler` owns it, because every love-milestone arm and cancel path goes through that class. It is not covered by backup, because the backup rules include media only, and it is cleared on breakup, sign-out, account switch and cancel-all. At boot it is replayed only while its owner account still has a session, the owner's own relationships are not all ended, and Room still holds the date the copy was written from.

**Tech Stack:** Kotlin, Jetpack Compose M3, Room v14, Robolectric, Roborazzi, kotlinx.datetime (alarm/plan), java.time with core library desugaring (`app/build.gradle.kts:105,176`).

Design, one lock-free fence, decided after tracing the code:

- Vault companion: `fence`, an AtomicLong. The low 32 bits count the transitions that are running and the upper bits count the transitions that have started. `transitionStamp()` returns -1 while a transition runs and otherwise a value that changes whenever one begins. It takes no lock: the replay holds `armLock` and the vault's `beforeSwitch` hook waits for `armLock`, so any wait of the replay on the vault would be a lock-order cycle.
- A transition is a whole scope switch or a whole pending-switch recovery. The fence is published before `beforeSwitch` and kept through `complete(...)`, so it covers the hook, the stash moves and the stored-scope write. `adoptCurrentInto` and the first-ever adoption write are not fenced: they run no hook and their scope write changes the stored token, which the replay's token checks already catch.
- Recovery (round-3 F2): `recoverPending()` runs `beforeSwitch` before `complete(...)`, inside its own fence, and a successful recovery counts as a changed scope: `switchTo` (including the recovery-only early return) and `adoptCurrentInto` call `afterSwitch` after it. A malformed marker is dropped and counts as nothing.
