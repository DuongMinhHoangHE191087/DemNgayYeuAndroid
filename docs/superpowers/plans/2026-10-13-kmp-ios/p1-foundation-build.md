## 1. Goal

Dựng nền build để InLove chạy được trên iOS mà Android luôn xanh sau từng task: thêm module KMP `:shared` (target `android` + `iosArm64` + `iosSimulatorArm64`) cạnh `:app` (Android thuần), khung `iosApp/` (Xcode, Swift host) nhúng framework `Shared` bằng Run Script `embedAndSignAppleFrameworkForXcode`, nâng bộ phiên bản theo bảng đã kiểm chứng (Kotlin 2.4.21, Compose Multiplatform 1.12.1, KSP 2.3.12, Room 2.8.5, JDK 21), thay `BuildConfig`/`manifestPlaceholders` bằng `AppConfig` + xcconfig, chốt quy trình hai máy Windows↔Mac (cổng GATE-A trên Windows, GATE-M trên Mac) và chạy spike P0 (12 task, F-01 đến F-12) có tiêu chí PASS/FAIL cùng quy tắc GO/STOP máy móc (gồm gõ tiếng Việt Telex/VNI trên iPhone thật) trước khi P2–P6 chuyển data, UI, native và monetization sang `:shared`.

## 4. Design / decisions

Mỗi quyết định là một dòng bắt đầu bằng `DECIDED:` (lựa chọn, bằng chứng, phương án bị loại). Chỗ lệch khỏi D1–D11 hoặc DEC-xx là dòng `DECISION-CONFLICT:`; P1 chỉ có một, ở đầu file (DEC-10). Tiêu chí theo thứ tự: mượt và ổn định, không bypass được, dễ mở rộng, ít việc nhất; hoà thì chọn ít phụ thuộc bên thứ ba.

### 4.1 Cấu trúc module và bố cục thư mục

DECIDED: Hai module Gradle `:app` (Android thuần, `com.android.application`, không `kotlin-android`) và `:shared` (`kotlin-multiplatform` + `com.android.kotlin.multiplatform.library`), cộng thư mục `iosApp/` là project Xcode nằm ngoài Gradle — vì AGP 9 dùng Kotlin tích hợp nên `kotlin-multiplatform` không chung module với `com.android.application` (A1) và D1 đã chốt dạng này — loại bỏ: một module `composeApp` kiểu mẫu JetBrains (AGP 9 không cho trộn plugin), tách `:domain`/`:data`/`:ui` (ba module KMP nhân ba lần cấu hình Gradle trên máy RAM thấp; chỉ tách khi link tăng dần của `:shared` vượt ngưỡng 120 s ở S7 mà cache không giảm được).

DECIDED: Giữ package gốc `com.example`, giữ lớp Room `data.db.AppDatabase`, đặt namespace Android của `:shared` là `com.example.shared` — vì thư mục schema Room khoá theo tên đầy đủ của lớp (A42) và namespace khác `com.example` của `:app` tránh hai module cùng sinh lớp `R` trùng tên — loại bỏ: đổi package sang tên mới (phá lịch sử migration 12 đến 14 và mọi import), dùng chung namespace `com.example` (va chạm lớp `R`).

```kotlin
class BootstrapStep(val name: String, val required: Boolean = false, val run: () -> Unit)

class BootstrapRunner(private val onError: (name: String, error: Exception) -> Unit) {
    fun run(steps: List<BootstrapStep>) {
        for (step in steps) {
            try { step.run() }
            catch (e: CancellationException) { throw e }
            catch (e: Exception) { onError(step.name, e); if (step.required) throw e }
        }
    }
}
```

DECIDED: Android: `androidBootstrapSteps(...)` trong `:app` (`app/src/main/java/com/example/bootstrap/AndroidBootstrapSteps.kt`) trả sáu bước theo thứ tự `firebase` (required), `app-check` (required), `service-locator` (required), `sync-worker` (required), `appplugin` (không required; gọi `super.onCreate()` trong lambda), `monetization` (không required); nhận sáu lambda làm tham số để test được thứ tự mà không cần `Context`; `isRunningInTest` vẫn trả sớm như hiện nay.
